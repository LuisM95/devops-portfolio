# CI/CD Documentation 

## What is CI/CD?

CI/CD stand for Continuos Integration and Continuos Delivery/Deployment. It automates the process of building, testing and deploying software, eliminating manual steps and reducing humans errors.

## CI vs CD 

- **CI (Continuos Integration):** automatically build and test code on every push 
- **CD (Continuos Delivery):** automatically delivers to staging, manual approval for productions
- **CD (Continuos Deployment):** fully automated all the way to production

## Why CI/CD in DevOps?

Without CI/CD:
- manual builds take hours
- Human errors in deployments 
- "Works in my pc", problems 
- Slow feedback loop

With CI/CD:
- Every commit is automatically tested
- Deployments are consistent and repeatable
- Fast feedback - Know in minutes if something broke 
- More time to write code, less time deploying 

## Github Actions 

CI/CD tool integrated into Github.

Workflows are defined in Yaml files inside `.github/workflows/`

## Key Concepts 

- **Workflow** -> The complete pipeline define in a YAML file 
- **JOB** -> a group of steps that run on the same server
- **Step** -> an individual task (run a command or use an action)
- **Action** -> a reusable task create by the community
- **Runner** -> the server where the job runs (ubuntu-latest)
- **Secret** -> encrypted variable stored in GitHub (passwords, tokens)


## Trigger Types

``` yaml
on:
  push:      #runs on every push 
    branches: [main]
  pull_request:     # runs on pull_request
  schedule:         # runs on a schedule (cron)
    - cron: "0 0 * * *"
  workflow_dispatch:  # manual trigger
```

## Pipeline Structure 

``` yaml  
name: CI/CD Pipeline

on: 
  push:
    branches: [main]

jobs:
  test: 
    runs-on: ubuntu-latest
    steps: 
      - uses: actions/checkout@v4
      - uses: actions/setup-python@4
        with:
          python-version: "3.11"
      - run: pip install pytest
      - run: pytest test/ -v

  build: 
    need: test    #only runs if test passes
    runs-on: ubuntu-latest
    steps: 
      - uses: actions/checkout@v4
      - uses: docker/login-action@v3
        with:
          username: ${{ secrets.DOCKER_USERNAME }}
          password: ${{ secrets.DOCKER_TONKEN }}
      - run: docker build -t myapp:latest .
      - run: docker push myapp:latest 
```

## Deployment Strategies 

- **Rolling Update:** -> replace pods gradually, zero downtime
- **Blue/Green:** -> two identicals environments, instant switch 
- **Canary:** -> small percentage of traffic to new version first

## Key Concepts 

- **Artifact:** files generated by the build (docker image, binary)
- **Cache:** store dependencies between runs to speed up pipeline
- **Needs:** define jobs dependencies (job B runs only if job A passes)
- **Secrets:** never hardcore credentials, always use GitHub Actions.
